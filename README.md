# Ассемблер и интерпретатор УВМ (вариант 28)

Учебный проект по дисциплине "Конфигурационное управление",
практическая работа 3. Разрабатываются ассемблер и интерпретатор для
учебной виртуальной машины (УВМ) с регистром-аккумулятором.

## Общее описание

Проект написан на Python 3 без сторонних библиотек и работает в
командной строке.

Этап 1 - перевод программы в промежуточное представление:

- ассемблер принимает путь к программе, путь к двоичному
  файлу-результату и ключ режима тестирования;
- язык ассемблера основан на формате JSON и поддерживает все команды
  спецификации УВМ;
- программа переводится во внутреннее представление: список команд
  с полями A и B;
- в режиме тестирования промежуточное представление выводится на
  экран в формате полей и значений, как в тестах спецификации;
- программа `programs/spec_tests.json` содержит все тесты
  спецификации и даёт те же поля и значения.

Этап 2 (текущий) - формирование машинного кода:

- промежуточное представление переводится в машинный код: поле A
  занимает младшие биты, поле B сдвигается на свой младший бит, число
  записывается от младшего байта к старшему;
- результат ассемблирования записывается в двоичный выходной файл;
- на экран выводится число ассемблированных команд (и размер кода);
- в режиме тестирования машинный код каждой команды выводится в
  байтовом формате, как в тестах спецификации (вывод промежуточного
  представления требовался только на этапе 1 и заменён байтами);
- трансляция `programs/spec_tests.json` даёт все тестовые байтовые
  последовательности спецификации.

## Спецификация УВМ

Поле A (биты 0-4) это код операции. Команда записывается в память от
младшего байта к старшему.

| Команда | A | Поле B | Размер | Действие |
| --- | --- | --- | --- | --- |
| загрузка константы | 30 | константа, биты 5-30 | 4 байта | аккумулятор = B |
| чтение из памяти | 29 | смещение, биты 5-20 | 3 байта | аккумулятор = память[аккумулятор + B] |
| запись в память | 28 | адрес, биты 5-21 | 3 байта | память[B] = аккумулятор |
| унарная операция sgn() | 3 | нет | 1 байт | аккумулятор = sgn(аккумулятор) |

Тесты из спецификации:

| Команда | Поля | Байты |
| --- | --- | --- |
| загрузка константы | A=30, B=847 | 0xFE, 0x69, 0x00, 0x00 |
| чтение из памяти | A=29, B=846 | 0xDD, 0x69, 0x00 |
| запись в память | A=28, B=697 | 0x3C, 0x57, 0x00 |
| sgn() | A=3 | 0x03 |

## Язык ассемблера

Программа это JSON-массив. Каждый элемент массива это объект с одной
командой, команды выполняются по порядку.

| Команда | Запись | Операнд (поле B) | Допустимые значения |
| --- | --- | --- | --- |
| загрузка константы | `{"op": "load_const", "constant": 847}` | `constant` | 0..67108863 (26 бит) |
| чтение из памяти | `{"op": "read", "offset": 846}` | `offset` | 0..65535 (16 бит) |
| запись в память | `{"op": "write", "address": 697}` | `address` | 0..131071 (17 бит) |
| sgn() | `{"op": "sgn"}` | нет | - |

Правила:

- поле `op` обязательно, это мнемоника команды;
- у команды должен быть ровно тот операнд, который указан в таблице,
  значение это целое неотрицательное число, которое помещается в
  поле B;
- в любой команде можно указать необязательное поле `comment` со
  строкой: JSON не поддерживает комментарии, а это поле ассемблер
  пропускает;
- другие поля считаются ошибкой.

Пример `programs/spec_tests.json` (тесты спецификации):

```json
[
  {"op": "load_const", "constant": 847, "comment": "тест A=30, B=847"},
  {"op": "read", "offset": 846, "comment": "тест A=29, B=846"},
  {"op": "write", "address": 697, "comment": "тест A=28, B=697"},
  {"op": "sgn", "comment": "тест A=3"}
]
```

## Промежуточное представление

Ассемблер переводит программу в список объектов `Instruction`. Каждый
объект хранит описание команды из спецификации (`CommandSpec`: имя,
код операции, размер, положение поля B) и значение операнда. Метод
`fields()` возвращает пары `("A", 30), ("B", 847)`, а запись объекта
строкой даёт `A=30, B=847`, как в тестах спецификации.

## Машинный код

Команда собирается в одно число: `слово = A | (B << младший_бит_B)`.
Число записывается в `размер` байт, младший байт первым.

Пример для `load_const 847`: 847 << 5 = 27104, 27104 | 30 = 27134 =
0x000069FE, байты от младшего: `0xFE, 0x69, 0x00, 0x00`.

Двоичный файл это машинный код всех команд подряд, без заголовка.

## Устройство программы

| Файл | Назначение |
| --- | --- |
| `src/main.py` | точка входа: выбор программы (`asm`) |
| `src/assembler.py` | командная строка ассемблера |
| `src/parser.py` | разбор JSON и проверка команд |
| `src/encoder.py` | перевод промежуточного представления в машинный код |
| `src/isa.py` | система команд УВМ и промежуточное представление |
| `src/errors.py` | виды ошибок |

## Функции

| Функция | Описание |
| --- | --- |
| `isa.CommandSpec.max_operand` | наибольшее значение поля B команды |
| `isa.Instruction.fields()` | поля команды: список пар (имя, значение) |
| `parser.load_program(path)` | прочитать файл и перевести программу в список `Instruction` |
| `parser.parse_program(text)` | перевести текст JSON в список `Instruction` |
| `parser.parse_command(item, number)` | перевести одну команду, в ошибке указывается её номер |
| `assembler.parse_args(argv)` | разобрать аргументы ассемблера |
| `encoder.encode_instruction(instruction)` | машинный код одной команды |
| `encoder.encode_program(program)` | машинный код программы: байты команд подряд |
| `encoder.format_bytes(data)` | записать байты как в спецификации: `0xFE, 0x69` |
| `assembler.print_bytes(program)` | вывести байты каждой команды |
| `assembler.write_binary(path, code)` | записать машинный код в файл, создав каталог |
| `assembler.main(argv)` | запуск ассемблера, возвращает код завершения |
| `main.main(argv)` | выбор программы по первому аргументу |

## Параметры ассемблера

```
run.bat asm <программа.json> <результат.bin> [-t | --test]
```

| Параметр | Описание |
| --- | --- |
| `программа.json` | путь к исходному файлу на языке ассемблера |
| `результат.bin` | путь к двоичному файлу-результату |
| `-t`, `--test` | режим тестирования: вывести машинный код каждой команды в байтовом формате |

## Обработка ошибок

Ассемблер выводит сообщение и завершается с кодом 1 (ошибка в
программе), если:

- файл программы не найден или JSON испорчен (указаны строка и
  столбец);
- программа не массив или в ней нет команд;
- команда не объект, нет поля `op`, команда неизвестна;
- нет операнда, операнд не целое число или не помещается в поле B;
- у команды есть лишние поля или `comment` не строка.

В сообщении указан номер команды. Примеры каждой ошибки лежат в
каталоге `programs/errors`.

Если двоичный файл не удалось записать (например, путь указывает на
каталог), код завершения 2.

## Сборка и запуск

Сборка не требуется, нужен Python 3.10 или новее.

```
run.bat asm programs\spec_tests.json out\spec_tests.bin --test   # Windows
./run.sh asm programs/spec_tests.json out/spec_tests.bin --test  # Linux и macOS
python -m src.main asm programs/spec_tests.json out/spec_tests.bin --test
```

Скрипты демонстрации:

| Скрипт | Что показывает |
| --- | --- |
| `scripts\stage1_ir.bat` | тесты спецификации в режиме тестирования и ошибки разбора |
| `scripts\stage2_bytes.bat` | машинный код тестов спецификации и содержимое двоичного файла |

Для Linux и macOS те же скрипты с расширением `.sh`. После этапа 2
режим тестирования выводит байты, поэтому скрипт этапа 1 тоже
показывает машинный код, а ошибки разбора остаются прежними.

## Запуск тестов

```
python -m unittest discover -s tests -t .
```

## Примеры использования

Тесты спецификации в режиме тестирования:

```
> run.bat asm programs\spec_tests.json out\spec_tests.bin --test
0xFE, 0x69, 0x00, 0x00
0xDD, 0x69, 0x00
0x3C, 0x57, 0x00
0x03
ассемблировано команд: 4 (11 байт)
```

Байты совпадают с тестами спецификации. Файл `out\spec_tests.bin`
содержит их подряд: `FE 69 00 00 DD 69 00 3C 57 00 03`.

На этапе 1 режим тестирования выводил промежуточное представление:

```
A=30, B=847
A=29, B=846
A=28, B=697
A=3
```

Ошибки:

```
> run.bat asm programs\errors\constant_too_big.json out\error.bin
ошибка ассемблера: команда 1 (load_const): значение constant=67108864 вне диапазона 0..67108863 (биты 5-30)

> run.bat asm programs\errors\unknown_command.json out\error.bin
ошибка ассемблера: команда 1: неизвестная команда 'add', допустимы: load_const, read, write, sgn
```
